# Cleany Explorer

끌리니의 CAD 모델을 돌려 보고 부품별 사양과 가격 근거를 확인하는 독립 웹서비스다. 부품을 가리키면 사양과 가격 요약이 표시되고, 클릭하면 상세 정보가 열린다. 모바일에서는 부품 선택기와 모델 번호 버튼으로 탐색한다.

화면은 창 높이에 맞춘 탐색 작업 공간이다. 데스크톱에서는 부품 목록, 3D 모델과 상세 패널을 나란히 표시한다. 사양과 참고 가격을 먼저 보여주고, 출처와 추가 견적은 **출처 · 가격 기준**에서 확인한다. 모바일은 부품 선택기와 **3D / 상세** 전환을 사용한다.

**ROS 연결도**의 기본 화면은 **실행 흐름**이다. 조작 실행, 집기 검증, 손목 카메라, 베이스 이동과 액션 내부를 선택해 토픽·서비스·액션의 호출, 발행과 참조 관계를 본다. 실물 Jetson, MuJoCo root와 Mock namespace를 구분하며 확인되지 않은 환경의 흐름은 비활성화한다. 선을 클릭하거나 키보드로 선택하면 조건과 코드 근거를 확인한다. 손목 흐름은 좌우를 전환하고 액션 내부에서는 다른 액션을 버튼으로 선택한다. 자동 생성 계약은 점선 카드로 표시하며 기본 인터페이스 수에 추가하지 않는다.

**부품 연결**로 전환하면 16개 부품과 처리 노드를 한 화면에 표시한다. 부품별 토픽, 서비스, 액션 수를 보고 선택하면 오른쪽 목록이 바뀐다. 인식, 조작, 주행, 미션, 시스템 기능으로도 탐색할 수 있다. 실물과 시뮬레이션 필터는 연결도와 목록에 함께 적용한다. 연결선 하나는 부품별 인터페이스 묶음이며, 하단 종류 버튼으로 실선·파선·점선과 목록을 함께 전환한다. 같은 종류를 다시 누르면 전체로 돌아온다.

목록은 **기본 이름 / ROS 자동 / 동적 이름**으로 구분한다. 종류 필터와 이름·타입·노드 검색을 조합하며, 화면 높이에 맞춰 페이지를 넘겨 전체 페이지 스크롤을 피한다. **목록 넓게**는 비교 영역을 확장한다. 행을 누르면 환경별 발행·구독 또는 호출·제공 경로, 조건과 로컬 소스 근거, 읽기 전용 조회 명령이 열린다. `/` 키는 현재 화면의 검색으로 이동한다.

부품에서 `/joint_states`를 열면 해당 부품의 관절 경로를 표시한다. **공유 토픽 전체 경로**로 전체 발행자와 구독자를 확인할 수 있다. 베이스 실행 흐름은 실물 MCU와 Mock MCU의 발행 경로를 각각 표시한다.

부품 상세의 **ROS** 탭에도 실물·시뮬레이션 선택과 카드 페이지 이동을 제공한다. **펼쳐보기**는 필터된 전체 항목의 비교표를 연다. **연결도**와 **3D 보기**로 왕복하며 `/#connections`로 직접 열 수 있다. 데이터는 소스 스냅샷이며 실시간 ROS 연결이나 로봇 제어 기능은 포함하지 않는다. 이번 ROS 작업 공간은 데스크톱에서 검증한다.

## 실행

Node.js 22.13 이상과 npm을 사용한다.

```sh
npm ci
npm run dev
```

개발 서버가 출력한 주소를 브라우저에서 연다. 개발 서버와 미리보기는 `127.0.0.1`에만 바인딩한다. `npm run build`는 로컬 `dist/`를 만들며, `npm run preview`로 확인한다. Google Fonts 연결이 실패하면 시스템 글꼴을 사용한다.

3D 코드와 CAD 파일은 **3D 탐색**을 처음 열 때 불러온다. 모델은 조작, 분해 전환이나 자동 회전 중에 렌더링하며, 정지 상태와 다른 화면에서는 반복 렌더링을 멈춘다. ROS 환경별 목록과 부품 연결 집계는 현재 소스 스냅샷에서 재사용한다.

## 데이터 갱신

부품별 사양, 상태, 출처와 가격은 `src/catalog.ts`에서 관리한다. 가격을 등록할 때 금액, 단위, 가격 유형, 확인일, VAT와 포함 범위를 함께 기록한다. 판매처 참고가와 견적은 근거 URL을 남기고, 사용자 제공가에 URL이 없으면 제공일과 비고를 기록한다. `scope: 'unit'`은 구성 수량을 곱하고 `scope: 'group'`은 세트나 전체 구성 금액을 한 번만 합산한다. `null`은 미등록이며 0원과 다르다. 관련 부품 참고 금액은 해당 모듈의 전체 가격과 구분하며 소계에 합산하지 않는다. CSV에도 가격 단위, 소계, VAT와 출처 구분을 함께 내보낸다. 카탈로그는 스냅샷으로, 구매처 가격을 실시간 갱신하지 않는다.

3D 탐색은 FreeCAD에 저장된 조립 자세를 보여준다. **케이스 벗기기**를 누르면 패널, 로고와 전면 화면이 숨겨지고 내부 부품 번호가 표시된다. **케이스 씌우기**로 복원한다. 내부 부품을 선택하면 케이스가 열리고, 케이스나 디스플레이를 선택하면 다시 씌운다. 부품별 근거는 [데이터 기준](docs/DATA.md)에서 확인한다.

FreeCAD 모델을 갱신하려면 `cleany_freecad_final.urdf`가 있는 원본 checkout을 사용한다.

```sh
python3 -B scripts/import-model.py /absolute/path/to/cleany-freecad-model-update --model freecad
npm test
npm run build
```

변환기는 원본 메시와 화면 텍스처를 그대로 복사한다. 원본 파일의 SHA-256, 조립 변환과 source commit은 `public/models/cleany.json`에 기록한다. 기존 Xacro를 읽으려면 xacro 2.1.1이 설치된 Python에서 `--model legacy`를 사용한다.

## ROS 데이터 갱신

`scripts/import-ros-catalog.py`는 전체 ROS 색인, Python/C++의 직접 인터페이스 선언과 확인한 launch/config 계약을 읽는다. 기본값을 정적으로 해결할 수 없는 이름은 동적 패턴으로 남긴다. 자동 생성 인터페이스는 인스턴스를 가정하지 않고 패턴으로 수록한다. 입력 레포의 코드를 실행하거나 수정하지 않는다.

```sh
python3 -B scripts/import-ros-catalog.py /absolute/path/to/cleany --date YYYY-MM-DD
```

`src/data/ros-catalog.json`에는 추출 결과와 선언별 추적 정보, `relationSources`에는 실행 흐름에서 검토한 소스의 키를 기록한다. `src/data/ros-sources.json`에는 입력 파일과 로컬 발췌문의 hash를 보관한다. 검토한 CLI namespace 기본값과 좌우 카메라 반복값은 구체적 이름으로 보완하고 원본 동적 선언도 유지한다. 보완에 사용한 소스 계약이 바뀌면 가져오기가 실패하므로 해당 관계를 재검토한다. `src/ros-reviewed.ts`의 설명·QoS는 경로별로 관리하며 환경·부품 선택에 맞춰 투영한다. `src/ros.ts`의 부품·기능 연결 규칙, 환경 분류와 `src/ros-relations.ts`의 실행 흐름도 입력 코드가 바뀔 때 함께 검토해야 한다. 실시간 그래프를 자동 추론하지 않는다.

기존 수동 근거 발췌문을 다시 가져오려면 `scripts/import-ros-sources.py`의 줄 범위를 먼저 검토하고 실행한 뒤, 위 catalog 가져오기를 다시 실행한다. 생성된 데이터와 출처를 같은 변경에 포함한다.

## 검증

`npm test`는 가격 누락 처리, 옵션 단가와 소계, 검색, CSV, 모델 자산 무결성과 연결 구조를 검사한다. 브라우저 검증 범위는 [검증 기록](docs/VALIDATION.md)에 남긴다.

ROS 검사는 근거 파일 무결성, 부품 매핑, 명령·피드백 방향, 좌우 팔 액션 분리, 종류·검색 교집합, 실물·시뮬레이션 구분과 조회 명령을 확인한다.

원본 에셋과 의존성의 출처는 [저작권 및 자산 안내](NOTICE.md)에 기록한다. 개발 서버는 로컬에서 실행한다.
